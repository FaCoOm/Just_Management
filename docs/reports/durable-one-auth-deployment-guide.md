# WithOne AuthKit Diagnosis

Date: 2026-07-11

## Current Verdict

The app-owned AuthKit proxy is working: `POST /api/one/auth-token?page=1&limit=50` returns `200` with the expected AuthKit response shape. WithOne accepts the request but returns `rows: []`. That proves transport and authentication succeeded; it does not identify why no integrations are visible.

## Verified Findings

1. No AuthKit integrations are visible to the current `ONE_SECRET_KEY`.
  - Direct WithOne token calls returned `200` with `rows=0` and `total=0` for `user`, `team`, `organization`, and `project` identity types.
  - The message `No integrations available. Please activate integrations from the AuthKit dashboard.` is generated by the WithOne widget, not this app.
2. Local frontend env was missing `VITE_ONE_DEV_TOKEN`.
  - `ConnectIntegrationButton` only sends `x-dev-token` when `VITE_ONE_DEV_TOKEN` exists.
  - The backend auth-token route rejects requests when the matching backend `ONE_DEV_TOKEN` gate is active and the header is missing or wrong.
3. Frontend env typings did not list the existing WithOne env names.
  - `frontend/src/env.d.ts` only typed `VITE_TRACK_B_API_URL`.
  - The component also reads `VITE_ONE_AUTH_ToOKEN_URL` and `VITE_ONE_DEV_TOKEN`.

## Repo-Owned Fixes

- Keep root `.env` `VITE_ONE_DEV_TOKEN` equal to backend `ONE_DEV_TOKEN` while the temporary gate exists.
- Type the existing frontend env names in `frontend/src/env.d.ts`.
- Keep `.env.example` documenting `VITE_ONE_AUTH_TOKEN_URL` and `VITE_ONE_DEV_TOKEN`.

## External Diagnosis

The remaining `rows=0` condition is external to the app proxy. Leading causes are integrations not enabled for AuthKit, an API-key organization/project scope mismatch, or a Sandbox/Production environment mismatch. CLI connections do not disprove these causes because the CLI and backend key can use different credential contexts.

Check the WithOne AuthKit dashboard for the exact key environment first. Enable at least one required integration, then repeat the same request. If results remain empty, compare the current key with a project-scoped key using identical connector and token requests. Do not describe key scope as the root cause without that A/B result.

## Verification Checklist

Run these without printing secret values:

```sh
curl -X POST "http://127.0.0.1:3001/api/one/auth-token?page=1&limit=50" \
  -H "Content-Type: application/json" \
  -H "x-user-id: dev-admin-1" \
  -H "x-dev-token: <same-value-as-ONE_DEV_TOKEN>" \
  -d "{}"
```

Pass condition before external configuration is resolved: status `200`, JSON keys include `rows,total,pages,page,requestId`. `rows=0` means token transport works but no AuthKit integrations are visible to this key; it does not distinguish activation, scope, or environment causes.

Pass condition after dashboard activation: status `200`, `rows.length > 0`, `total > 0`.

Also verify CORS preflight for both origins:
